# KB Resume System (Figma 개발 플러그인)

Figma 데스크톱 앱 안에서 "KB 이력서 디자인 시스템"을 만들고, JSON 내용으로 이력서·자기소개서·포트폴리오 페이지를 한 번에 만드는 플러그인입니다. 빌드 과정 없이 `code.js`, `ui.html`, `manifest.json` 세 파일로 동작합니다.

- 디자인 스펙: `docs/SPEC.md`, 그 위에 덮어쓰는 `docs/SPEC2.md`(B형 원본 실측, 충돌 시 우선)
- 레이아웃 기준: `docs/preview.html` (승인된 HTML 미리보기. 간격·페이지 나눔 규칙이 이 파일과 같습니다)
- 내용 JSON 형식: `docs/content.schema.json`
- 샘플 내용: `docs/sample.json`

## 1. Figma 데스크톱에 가져오기

1. Figma **데스크톱 앱**에서 대상 파일을 엽니다. 브라우저 Figma 에서는 개발 플러그인을 가져올 수 없습니다.
2. 메뉴에서 **Plugins → Development → Import plugin from manifest…** 를 고릅니다.
3. 이 폴더의 `manifest.json` 을 선택합니다.
4. 이후에는 **Plugins → Development → KB Resume System** 으로 실행합니다.

코드를 고친 뒤에는 플러그인 창을 닫고 다시 실행하면 새 코드가 반영됩니다. `manifest.json` 이 바뀐 경우(이번 버전은 이미지 URL 때문에 네트워크 권한이 바뀌었습니다)에는 Figma 를 한 번 재시작하는 편이 안전합니다.

## 2. 실행 순서

모든 단계는 **이름으로 찾고, 없을 때만 만듭니다.** 몇 번을 다시 눌러도 중복이 생기지 않습니다. 로그에 `exists → skipped` 또는 `created` 가 찍힙니다. `Page 1` 은 절대 건드리지 않습니다.

| 버튼 | 하는 일 |
|------|---------|
| 1. Foundations | `Design System`·`Templates` 페이지, 섹션 4개, 변수 컬렉션 `KB Tokens` 의 변수 40개, 텍스트 스타일 28개를 확인하고 없으면 만듭니다. 값이 스펙과 다르면 스펙 값으로 고칩니다. 마지막으로 위에서 고른 폰트를 28개 스타일에 적용합니다(코드 블록용 `KB/Code` 는 고정폭 폰트 유지). |
| 2. Atoms | `Atom/*` 11개를 확인하고 빠진 것만 `2 Atoms` 섹션에 만듭니다. |
| 3. Blocks | `Block/*` 15개를 `3 Blocks` 섹션에 만듭니다. 왼쪽 열(x=80)은 이력서·자소서, 오른쪽 열(x=1280)은 포트폴리오 블록입니다. |
| 4. Templates | `Templates` 페이지에 `Template/Resume`, `Template/PortfolioCover`, `Template/PortfolioDetail`, `Template/CoverLetter` 를 y=0 한 줄로 만듭니다. |
| 5. Build all (JSON 전체) | 붙여넣은 JSON 에 들어 있는 페이지를 전부 만듭니다. A4 를 넘치면 자동으로 다음 장으로 나눕니다. 아래 3장을 보세요. |
| advanced: 템플릿 하나만 채우기 | 접힌 메뉴 안에 있습니다. 종류 하나(포트폴리오 상세는 `details[번호]` 하나)만 같은 방식으로 만듭니다. |
| 6. PNG 내보내기 | 선택한 노드를 1배율 PNG 로 내려받습니다. 파일 이름은 노드 이름입니다. |
| 선택한 페이지 색 고정 | 선택한 페이지 안의 강조색·본문색 변수 연결을 풀고 지금 색을 그대로 박아 둡니다. 아래 "테마 색상" 을 보세요. |

오류가 나면 로그에 단계 이름과 메시지, 스택 일부가 빨간색으로 찍힙니다. 그 줄을 그대로 복사해 전달해 주세요.

### 이전 버전에서 업데이트할 때

구조가 바뀐 컴포넌트는 버전 표식(`kbv`)으로 알아봅니다. 표식이 낮은 컴포넌트는 이름 뒤에 `(구버전 vN)` 을 붙여 보관하고 새 버전을 만듭니다. 보관본은 지우지 않습니다. 예전에 채운 페이지가 여전히 그것을 참조하기 때문입니다. 보관된 템플릿은 원래 자리 위쪽(y 가 음수)으로 옮겨 둡니다.

**SPEC2 반영본으로 올릴 때는 1 → 2 → 3 → 4 → 5 를 누르세요.**

| 단계 | 이번에 하는 일 |
|------|----------------|
| 1. Foundations | 새 텍스트 스타일 4개(`KB/Title/SkillResume` 20/29, `KB/Detail/Heading` 16/22, `KB/Caption/Image` 14/17, `KB/Code` 13/18 고정폭)를 만듭니다. |
| 2. Atoms | `Atom/Rule/Short` 를 세로 바 2×27 로 다시 만듭니다. |
| 3. Blocks | `Block/SectionHeader`, `Block/PageTitle`, `Block/Resume/AboutPara`, `Block/Resume/EducationItem`, `Block/Cover/ProjectItem`, `Block/Detail/Side`, `Block/Detail/Summary` 를 다시 만들고, `Block/Resume/SkillGroup`, `Block/Detail/ProjectHead` 를 새로 만듭니다. |
| 4. Templates | 템플릿 4개를 모두 다시 만듭니다. |
| 5. Build all | 새 규칙으로 페이지를 만듭니다. |

- 이전 버전의 `Block/Detail/Project`, `Block/Detail/Section` 은 더 이상 쓰지 않습니다. 파일에 남아 있어도 됩니다.
- 순서를 건너뛰면 다음 단계가 "구버전 Block" 이나 "텍스트 스타일 없음" 오류로 멈추고 어느 단계를 다시 누를지 알려 줍니다.

## 3. Build all: JSON 전체로 페이지 만들기

1. `docs/sample.json` 을 복사해 내용을 고칩니다. 예를 들어 경력을 추가하려면 `resume.experience` 배열에 항목을 하나 넣습니다.
2. JSON 전체를 플러그인 창의 입력칸에 붙여넣습니다. 마지막으로 붙여넣은 내용은 창을 다시 열어도 남아 있습니다.
3. 이미지가 파일 이름으로 적혀 있으면 **이미지 폴더 선택/드롭** 으로 폴더를 넘깁니다. 아래 "이미지" 를 보세요.
4. **5. Build all (JSON 전체)** 를 누릅니다.

만드는 순서는 `resume` → `coverLetter` → `portfolio.cover` → `portfolio.details[0]`, `[1]`, … 입니다. JSON 에 없는 키는 건너뜁니다.

- 페이지는 `Templates` 페이지의 y=1984 줄에 x = 순번 × 1290 으로 놓입니다. 이미 채운 페이지가 있으면 그 오른쪽부터 이어 붙입니다.
- 이름은 `<이름>_<종류>_<쪽번호>_<날짜>` 입니다. 예: `홍길동_resume_2_2026-10-13`. 포트폴리오 상세는 회사마다 따로 묶여서 종류가 `portfolioDetail-0`, `portfolioDetail-1` 처럼 붙고, 쪽번호는 회사마다 1부터 셉니다.
- 끝나면 만든 페이지 전부가 선택되고, 로그에 페이지 ID 가 찍힙니다.
- 다시 누르면 기존 페이지를 지우지 않고 새로 한 벌을 오른쪽에 더 만듭니다. 필요 없는 쪽은 직접 지우세요.

채운 페이지는 템플릿 인스턴스를 **detach 한 프레임**입니다. 항목을 자유롭게 늘리고 다음 장으로 옮기기 위해서입니다. 안의 블록(제목, 경력 항목 등)은 계속 컴포넌트 인스턴스라서, 블록 컴포넌트를 고치면 채운 페이지에도 반영됩니다. 예외는 두 가지입니다.

- **불릿이 있는 본문.** 본문에 `• ` 줄이 있는 항목(프로젝트 항목, 불릿이 있는 About Me 단락)은 매달림 들여쓰기를 px 단위로 맞추려고 그 항목만 detach 하고 본문을 줄 단위 프레임으로 바꿉니다. 그 안의 선·링크 같은 Atom 은 계속 인스턴스입니다.
- **포트폴리오 상세 본문 블록.** 블록(section / image / images / code)은 JSON 에 따라 코드가 만드는 프레임입니다. 프로젝트 머리(`Block/Detail/ProjectHead`)와 사이드바(`Block/Detail/Side`)는 인스턴스입니다.

본문 문자열 규칙은 다음과 같습니다.

- `**굵게**` 는 같은 폰트의 Bold 로 바뀝니다.
- `[보이는 글자](https://주소)` 는 밑줄 링크가 됩니다.
- 줄바꿈은 `\n` 입니다.
- 경력·프로젝트의 `url` 은 제목 전체에 링크로 걸립니다.
- 줄이 `• ` 로 시작하면 1단계 불릿, 공백 2칸 이상 뒤 `• ` 면 2단계 불릿(+24)입니다. 불릿 글자 뒤 1em(16) 에서 글이 시작하고, 줄이 넘어가도 그 위치에 맞춰 매달립니다.
- 불릿 안에서 손으로 줄을 바꾼 이어지는 줄은 평문 앞에 공백을 둡니다. 공백 2~3칸이면 1단계 불릿 글 위치, 4칸 이상이면 2단계 불릿 글 위치에 맞춰 들여씁니다.
- `bullets` 배열 항목 안의 `\n` 은 그 불릿의 이어지는 줄이 됩니다.
- `## 텍스트` 줄은 강조색 16 Bold 소제목입니다(포트폴리오 상세 section 블록에서만).

### 페이지 나눔 규칙

`docs/preview.html` 의 `paginate()` 와 같은 규칙에, SPEC2 의 포트폴리오 상세 블록 규칙을 더했습니다.

- 항목을 하나 넣을 때마다 페이지 내용의 아래 끝을 잽니다. 기준은 A4 높이 1684 에서 아래 여백 30 을 뺀 1654 입니다.
- 넘치면 그 항목을 새 페이지로 옮깁니다. 새 페이지 맨 위에는 섹션 제목을 다시 붙입니다. 이어지는 쪽의 제목에서는 우측 별표 안내문을 뺍니다.
- 섹션의 첫 항목부터 넘치면 그 섹션 제목째로 다음 장으로 넘어갑니다.
- 이력서의 이어지는 장은 위 여백이 44 입니다(첫 장 섹션 제목은 y=233).
- 나누는 단위는 About Me 단락, 경력 항목, 학력 항목, 프로젝트 항목, 스킬 그룹, 자기소개서 단락, 표지 프로젝트 항목입니다. 표지의 Profile(사진+스킬)은 한 덩어리입니다.
- 헤더(이름, 로고, 연락처)는 첫 장에만 있습니다.
- **포트폴리오 상세는 블록 단위**로 나눕니다. 블록이 넘치면 그 블록부터 새 장으로 옮기고, 새 장 맨 위(y=64)에 그 프로젝트의 제목·부제·밑줄을 다시 붙입니다. 사이드바는 다시 붙이지 않습니다. 회사명도 이어지는 장에는 없습니다.
- 프로젝트의 첫 블록부터 넘치면 프로젝트 전체(머리, 사이드바, 첫 블록)를 새 장으로 옮깁니다.
- 항목이나 블록 하나가 A4 한 장보다 크면 그대로 두고 로그에 경고를 남깁니다. 본문을 줄이거나 나누세요.

### 이미지

이력서 `resume.logo`, 자기소개서 `coverLetter.photo`, 포트폴리오 표지 `portfolio.cover.photo`, 상세 프로젝트의 image·images 블록 `src`(옛 형식의 `image` 포함)는 자동으로 들어갑니다. 값은 세 가지 형태를 받습니다.

| 형태 | 예 | 처리 |
|------|----|------|
| URL | `https://example.com/a.png` | 플러그인이 직접 내려받습니다. |
| data URI | `data:image/png;base64,iVBOR…` | 창(UI)에서 base64 를 풀어 넘깁니다. |
| 파일 이름 | `coaching-page.png` | 창에서 고른 이미지 폴더에서 같은 이름의 파일을 찾습니다. 경로가 붙어 있어도 마지막 파일 이름만 봅니다. |

- 파일 이름을 쓰려면 **이미지 폴더 선택/드롭** 을 눌러 폴더를 고르거나, 폴더나 파일을 그 칸에 끌어다 놓습니다. 하위 폴더까지 읽습니다. 예: `docs/images`.
- 플러그인에는 JSON 이 실제로 가리키는 파일만 보냅니다.
- 고른 이미지는 창을 닫으면 사라집니다. 창을 다시 열면 폴더를 다시 고르세요.
- 상세 image 블록은 잘리지 않습니다(FIT). 폭은 994(또는 `width`), 높이는 이미지 비율대로이며, 높이가 420 을 넘으면 높이 420 에 폭을 비율대로 줄입니다. 콘텐츠 열(105 → 1135) 가운데 정렬이고, 캡션은 14/17 가운데 정렬로 이미지 8 아래에 붙습니다.
- 상세 images 블록은 가로로 나란히, 같은 높이(최대 220, 소수점 버림)로 놓고 묶음 전체를 가운데 정렬합니다. 폭은 각 비율대로(소수점 버림)이고, 합이 994 를 넘으면 높이를 줄여 맞춥니다. 간격은 `gap`(기본 24)입니다.
- 표지 사진(410×374)과 자기소개서 원형 사진(168×171)은 자리를 꽉 채우도록(FILL) 잘립니다.
- 이력서 로고는 높이 60(`resume.logoHeight` 로 변경), 폭은 비율대로 최대 270 입니다. x 는 이름 오른쪽 끝 + 20, y 는 55 이고 잘리지 않습니다(FIT). 페이지 프레임의 절대 위치 자식이라 페이지 나눔에 영향을 주지 않습니다.
- 값이 비어 있으면 표지·자소서 사진은 회색 자리 그대로 둡니다.
- 파일을 찾지 못했거나 불러오지 못하면 로그에 경고를 남기고 그 자리를 숨깁니다. 상세 블록은 그 블록을 건너뜁니다.
- Figma 가 받는 형식은 PNG, JPG, GIF 입니다. 가로·세로 4096px 이하여야 합니다.

### 테마 색상

JSON 최상위에 `theme` 을 넣으면 Build all·Fill 을 시작할 때 `KB Tokens` 의 색 변수 값을 바꿉니다.

```json
"theme": { "accent": "#f9af00", "ink": "#101010" }
```

- `accent` 는 `color/accent`(노란 점, 별표, 태그라인, 소제목), `ink` 는 `color/ink`(본문, 제목, 구분선)입니다. 둘 다 선택입니다.
- JSON 에 `theme.accent` 가 없으면 플러그인 창의 **강조색** 값을 씁니다. JSON 값이 우선합니다. 창의 강조색은 기본이 원본 색 `#f9af00` 이라, 그대로 두면 원본 색으로 돌아갑니다.
- 적용한 색은 로그에 남습니다.
- **주의:** 색은 변수 하나를 바꾸는 방식이라, 그 변수를 쓰는 **이미 만든 페이지 색도 함께 바뀝니다.** 회사마다 다른 색을 유지하려면 페이지를 만든 직후 그 페이지들을 선택하고 **선택한 페이지 색 고정** 을 누르세요. 그 페이지 안의 강조색·본문색은 변수 연결이 풀리고 지금 색 값이 박힙니다. 그 뒤 다른 색으로 Build all 을 해도 고정한 페이지는 바뀌지 않습니다.
- 색을 고정한 페이지는 이후 변수 변경을 따라가지 않습니다. 되돌리려면 그 페이지를 지우고 다시 만드세요.

## 4. 레이아웃 규칙 (SPEC2 실측)

**페이지 여백.** 좌우 55, 아래 30 은 공통입니다. 위 여백은 템플릿마다 다릅니다.

| 템플릿 | 첫 장 위 여백 | 이어지는 장 |
|--------|---------------|-------------|
| Resume | 37 (`space/page-top` 변수) | 44 |
| CoverLetter | 55 | 55 |
| PortfolioDetail | 66 | 64 |
| PortfolioCover | 74 | 74 |

## 6. 실행 시 확인 필요

Figma 없이 작성해서, 아래 API 동작은 실제 실행에서 확인이 필요합니다. 문제가 생기면 로그 줄을 그대로 전달해 주세요.

1. **레이아웃 즉시 반영.** 항목을 넣은 직후 `y`·`height` 를 읽으면 auto layout 이 다시 계산된 값이 나온다고 가정합니다. 페이지 나눔과 세로선 위치가 모두 이 가정에 기댑니다.
2. **`figma.createImageAsync(url)`.** `manifest.json` 의 `allowedDomains: ["*"]` 와 `reasoning` 으로 허용된다고 가정합니다. 이미지 서버가 CORS 를 막으면 실패하고 경고 후 자리를 숨깁니다.
3. **UI → 플러그인 `Uint8Array` 전달.** `postMessage` 로 이미지 바이트가 그대로 넘어온다고 가정합니다. 일반 객체로 바뀌어 와도 다시 `Uint8Array` 로 바꾸는 처리를 넣었습니다.
4. **`webkitdirectory` 폴더 선택과 폴더 드롭.** 플러그인 창(iframe)에서 폴더 선택과 `webkitGetAsEntry()` 가 동작한다고 가정합니다. 안 되면 파일 여러 개를 직접 끌어다 놓으세요.
5. **인스턴스 안 노드의 채우기·표시 덮어쓰기.** 자소서 헤더 인스턴스 안 `photo` 원에 IMAGE fill 을 덮어씁니다. 상세 이미지는 코드가 만든 사각형이라 해당하지 않습니다.
6. **`layoutPositioning = 'ABSOLUTE'`.** detach 한 페이지 프레임에 사각형을 넣고 절대 위치로 바꾼 뒤 x=66, y 를 지정합니다.
7. **`detachInstance()` 뒤 `clone()`.** 페이지·섹션·항목을 복제한 뒤 `appendChild`·`insertChild` 로 옮깁니다. 복제본이 처음에 어느 부모에 붙는지와 무관하게 항상 명시적으로 옮깁니다.
8. **세로 FILL.** 표지 연락처 표의 세로선은 hug 높이 가로 auto layout 안에서 `layoutSizingVertical = 'FILL'` 로 세 줄 높이를 따라간다고 가정합니다.
9. **boolean 속성 기본값.** `showRule`, `showRightText` 를 기본값 false 로 만들 때 노드를 먼저 숨긴 뒤 속성에 연결합니다. 기본값과 노드 표시 상태가 어긋나지 않는지 확인이 필요합니다.
10. **`figma.base64Decode`.** UI 가 data URI 를 풀지 못했을 때만 쓰는 대체 경로입니다.
11. **이미지 크기 읽기.** `figma.getImageByHash(hash).getSizeAsync()` 로 원본 크기를 읽어 상세 image·images 블록과 이력서 로고의 크기를 정합니다. 크기를 못 읽으면 image 블록은 994×420, 로고는 270×60 에 FIT 으로 넣고 경고합니다.
12. **색 고정.** 선택 노드와 인스턴스 안 노드까지 훑으며 `boundVariables.color` 가 `color/accent`·`color/ink` 인 SOLID 칠·선을 변수 없는 같은 색으로 바꿉니다. 인스턴스 안 노드 덮어쓰기와 텍스트 노드 칠 교체(폰트를 먼저 불러옴)가 되는지 확인이 필요합니다. 구간마다 색이 다른 텍스트는 건너뜁니다.
13. **`setPluginData('kbv', …)`.** 컴포넌트 버전 표시에 씁니다. 이 값이 없는 예전 컴포넌트는 v1 로 봅니다.
14. **항목 detach 후 본문 교체.** 불릿 본문이 있는 항목 인스턴스를 `detachInstance()` 한 뒤 본문 텍스트 자리에 줄 단위 프레임을 `insertChild` 로 넣고 원래 텍스트를 지웁니다. detach 한 항목이 원래 자리·FILL 폭을 유지한다고 가정합니다.
15. **인스턴스 안 노드 표시·패딩 덮어쓰기.** 프로젝트 항목의 `tool1`~`tool10` 텍스트, 사이드바의 `link1`~`link3` 행·`tag1`~`tag8` 은 표시 여부를 직접 덮어씁니다. 상세 회사명 점 간격(9)은 인스턴스 안 `dotWrap` 의 `paddingLeft` 를 덮어씁니다. 실패하면 로그에 경고만 남깁니다.
16. **고정폭 폰트.** `listAvailableFontsAsync` 로 Menlo → Roboto Mono → Source Code Pro 순서로 찾습니다. 하나도 없으면 선택 폰트 Regular 로 바꾸고 경고합니다.
17. **사이드바 옆/아래 판정.** 블록을 넣을 때마다 옆 열과 사이드바의 `height` 를 읽어 비교합니다. 1번(레이아웃 즉시 반영)에 기대는 부분입니다.
18. **고정 높이 줄에서 넘치는 자식.** 이력서 섹션 제목 줄은 높이 38 고정이고, 안내문 묶음(48)은 아래 정렬로 위쪽 10 이 줄 밖으로 나갑니다. 학력 항목(27 고정)의 학과도 아래로 3 넘칩니다. `clipsContent` 를 끈 auto layout 에서 이렇게 그려진다고 가정합니다.
19. **고정 폭 항목.** 이력서 스킬 그룹은 목록 안에서 폭 1081 고정이라 오른쪽으로 4 넘칩니다(설명 오른쪽 끝 1137). 같은 가정입니다.
